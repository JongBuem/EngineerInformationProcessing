Java — 다형성과 동적 디스패치

Java · Polymorphism · Overriding · Overloading · Dynamic Dispatch
Q문제 코드
Java 다형성 · 오버라이딩 · 동적 디스패치
Java 
class A {
    String f(Object x) {
        return "1";                 // A의 f(Object): 인자 타입 Object
    }
    String g() {
        return f("a");             // A 관점에서 오버로딩 해결 → f(Object) 선택
    }
}

class B extends A {
    String f(Object x) {         // A의 f(Object)를 오버라이드 → 동적 디스패치 대상
        return "2";
    }
    String f(String x) {         // 오버로드 — f(Object)와 별개 시그니처
        return "3";
    }
}

public class Main {
    public static void main(String[] args) {
        A a = new B();           // 선언타입=A, 실제객체=B
        System.out.println(a.g());
    }
}

위 코드의 출력값은 무엇인가?

System.out.println() 출력 결과
2
g()→f(Object) 오버로딩 해결(컴파일) + B의 f(Object) 동적 디스패치(런타임)
① 문제 유형

Java 동적 디스패치(Dynamic Dispatch): 오버로딩 후보는 컴파일 타임 선언 타입 기준으로 결정되고, 오버라이딩된 메서드는 런타임 실제 객체 타입 기준으로 호출되는 두 단계의 차이를 묻는 문제입니다.

② 연쇄 호출 단계별 분해
1 A a = new B() → 선언타입=A, 실제객체=B 참조변수는 A, 힙의 객체는 B
2 a.g() 호출 → A의 g() 실행 B에 g() 없음 → A.g() 그대로
3 A.g() 내부: f("a") → 컴파일 타임: f(Object) 선택 A 관점에서 f(String) 없음 → f(Object)만 후보
4 런타임: 실제 객체 B → B의 f(Object) 호출 동적 디스패치: B가 f(Object) 오버라이드
5 B.f(Object) return "2" → println("2") 출력 최종 출력
③ 오버로딩 vs 오버라이딩 — 두 단계 비교
구분결정 시점기준이 문제에서
오버로딩 해결 컴파일 타임 선언 타입 A A에 f(Object)만 있음 → f(Object) 선택
동적 디스패치 런타임 실제 객체 B B가 f(Object) 오버라이드 → B.f(Object)="2"
④ 함정 — 왜 "3"이 나오지 않는가?
  • ⚠️B의 f(String)은 A에 존재하지 않는 메서드 → A 관점에서 오버로딩 후보에 없음
  • ⚠️오버로딩 후보 탐색은 컴파일 타임에 선언 타입(A) 기준으로 끝남
  • ✅런타임 동적 디스패치는 오버라이딩된 f(Object)만 대체 대상 — f(String)은 새 메서드이므로 해당 없음
System.out.println() 출력 결과
2
컴파일: f(Object) 선택 | 런타임: B의 f(Object) 동적 호출 → "2"
